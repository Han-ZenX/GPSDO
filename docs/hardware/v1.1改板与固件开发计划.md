# GPSDO v1.1 改板与固件开发计划

> **本计划的依据与前提。** 硬件现状由 `hardware/schematic/v1.0` 工程文件解析并经 `kicad-cli` 导出网表核对；固件现状由 `firmware/` 下的实际代码统计。改动理由来自同目录的三份文档：`OCXO选型文档`、`GNSS模组选型文档`、`开源GPSDO项目对比文档`。
>
> **关键前提：本计划假设走"真 OCXO + 便携锂电"路线**（即 OCXO 选型文档里的路线 1/2），而不是改用超稳 MEMS 的路线 3。如果决定改走 MEMS，本文的 HW-1、HW-2 中关于 5 V 升压与 EFC 模拟链路的全部内容失效，固件的 M4 与 M5 需要重写为 I²C 数字调频。**若路线未定，请先定这个，再看第 2 节。**

---

## 1. 现状盘点

### 1.1 硬件：基本完整，有五处待改

v1.0 的整体架构是对的——MCU、GNSS、OCXO、时钟缓冲、电源管理、USB、充电、按键、蜂鸣器都已就位，PCB 已布完。问题集中在 OCXO 供电能力、EFC 模拟链路、GNSS 定时能力这三块，详见第 2 节。

### 1.2 固件：实际上是空的

这是本计划里最需要正视的事实。

| 文件 | 行数 | 实际内容 |
| --- | --- | --- |
| `src/main.c` | 32 | 调用三个空函数的框架 |
| `src/app/app_main.c` | 16 | 空函数 |
| `src/hal/hal_init.c` | 13 | 空函数 |
| `src/services/service_manager.c` | 13 | 空函数 |
| `boards/default/board_config.h` | 36 | **模板，且内容与实际硬件矛盾** |
| **合计** | **194** | **没有任何 GPSDO 功能代码** |

没有 NMEA 解析、没有定时器捕获、没有 PI 控制环、没有 PWM 输出、没有 ADC 采集、没有状态机、没有数据记录。**固件是从零开始，不是改进。**

### 1.3 三处文档与实物不一致，必须先修正

| 位置 | 当前内容 | 实际硬件 |
| --- | --- | --- |
| `boards/default/board_config.h` | `MCU_TYPE "STM32F407"`，`SYSTEM_CLOCK_HZ 168000000` | **STM32G431KBU6，170 MHz** |
| `board_config.h` 引脚定义 | PA9/PA10 UART、PA4-PA7 SPI、PB6/PB7 I2C、PC13 LED、PA0 按键 | 见 3.1 节实测表。**UFQFPN32 封装没有 PC13**；PA0 是 10 MHz 输入不是按键；SPI 根本没用 |
| `hardware/pinout/pinout.md` | 十行通用模板 | 同上 |
| `README.md` 硬件规格 | 列了 ADS1115/ADS1258、TMP117、PCF8563 | **原理图里都不存在**。板上唯一的 I²C 设备是 BQ25890 |

### 1.4 构建系统还不能产出可烧写固件

`firmware/CMakeLists.txt` 没有交叉编译工具链文件、没有 `CMAKE_SYSTEM_NAME`、没有链接脚本、没有启动文件、没有引入 STM32 HAL 或 LL 库。全仓库只有 `ci/workflows/build.yml` 里装了 `gcc-arm-none-eabi`，但 CMake 侧并未使用它。

**现在执行 README 里的 `cmake -B build -DBOARD=default` 只会用主机编译器编译三个空文件，产出一个 x86 可执行文件。** 这是 M0 存在的原因。

## 2. 硬件改动清单

### 2.1 P0 必改（不改则达不到设计目标）

#### HW-A　OCXO 供电：解决 5 V 与电流上限

| 项 | 内容 |
| --- | --- |
| 问题 | `+3.3/+5V` 轨由 TPS7A8901 线性稳压，输入是 SYS（3.0–4.4 V），**结构上做不出 5 V**；单通道约 500 mA，3.3 V 下仅 1.65 W，而典型 OCXO 预热要 3–6 W，**会触发限流反复重启** |
| 来源 | OCXO 选型文档 2.2 节 |
| **方案 A（低成本，优先评估）** | **复用 BQ25890 的 OTG 升压**。U5 的 OTG 控制脚已连到 MCU 的 PB3，BQ25890 的 OTG 模式能从电池升压出 5 V 到 VBUS，典型能力 1.2–2.4 A。**这意味着可能不需要新增升压 IC** |
| 方案 A 的风险 | OTG 输出在 VBUS 上，需要把 VBUS 引回板内给 OCXO，必须处理：USB 插入时的冲突与反灌、OTG 使能时序、USB 供电与电池供电的切换逻辑。**这几点必须在改板前用 BQ25890 datasheet 确认清楚** |
| 方案 B（稳妥） | 新增独立升压 IC（能力 ≥1.5 A）后串一级超低噪 LDO 稳到 5.0 V。多 6 个元件，但逻辑简单、无耦合风险 |
| 共同要求 | 升压是开关电源，纹波会经供电灵敏度调制频率并抬高相噪底，**必须串一级低噪 LDO，留 300–500 mV 压差** |
| 顺带 | R10/R11 的值目前是占位符（写成 "100nF" 和 "GND"），需定为实际反馈电阻 |
| 验证 | 用限流电源模拟 OCXO 预热负载（0.2→1.0 A 阶跃），测 5 V 轨的跌落与恢复；用示波器测纹波 |

#### HW-B　EFC 加运放缓冲

| 项 | 内容 |
| --- | --- |
| 问题 | EFC 节点源阻抗 **40 kΩ**（R4+R5 各 20 kΩ）。OCXO 的 EFC 输入阻抗 Rin 会与之分压，Rin=100 kΩ 时只剩 71%，且 Rin 随温度变化转成控制增益漂移 |
| 来源 | OCXO 选型文档 风险 A；**并且开源 GPSDO 对比文档发现 Carsten Andrich 的 STM32G4 方案正是这么做的**——他在调谐 DAC 之后加一级 1 Hz 有源低通 |
| 方案 | 在二阶 RC 之后加一级轨到轨运放电压跟随器（OPA333 或 OPA192 级别，低失调低噪声）。或按 Andrich 的做法把第二级 RC 直接做成有源低通，一次解决滤波与阻抗两件事 |
| 代价 | 1 颗运放 + 2 个无源件 |
| 验证 | 串入 100 kΩ 前后测 VCTL 电压变化，加缓冲后应无可测变化 |

#### HW-C　GNSS 换定时级模组

| 项 | 内容 |
| --- | --- |
| 问题 | SKG123N 是**导航级**模组，没有定时模式，1PPS 受位置解算噪声污染；而且**没有锯齿波修正消息** |
| 来源 | GNSS 模组选型文档 第 3、6 节 |
| 方案 | 换 **u-blox NEO-F10T**（L1+L5 双频定时级）或 **NEO-M8T**（单频、资料最全）。**本板焊盘是 12.20×16.30 mm / 24 pad，与 u-blox NEO 封装尺寸一致，且 pin 3=1PPS、10=GND、11=RF_IN、23=VCC 四个关键脚已核对对应，改板量可能为零** |
| **前置条件** | 必须先完成 GNSS 文档第 7 节的 24 脚逐一核对。**这件事没做完之前不要下单** |
| 若脚位不兼容 | 退回 SkyTraq PX1100T（10.1×9.7 mm，5 ns，支持 PSTI,00），代价是重画焊盘 |
| 验证 | 见 GNSS 文档第 8 节；核心是 M4 完成后锯齿波修正前后的抖动对比 |

#### HW-D　输出链路复核

| 项 | 内容 |
| --- | --- |
| 问题一 | R6 180 Ω 与 R24 49.9 Ω 构成分压，把 3.3 Vpp 方波衰减到约 **0.72 Vpp**，可能低于 LMK1C1102 的输入高电平门限 |
| 问题二 | PCB 中 **U8（LMK1C1102）的 VDD 焊盘 pad 6 当前未连接** |
| 来源 | OCXO 选型文档 风险 C |
| 方案 | 核对 U8 的 V_IH/V_IL，串阻改 22–33 Ω；连上 U8 的 VDD |
| 注意 | 问题二若确实存在，**当前板子的时钟缓冲根本不工作**，这会掩盖其他所有问题，应优先确认 |

#### HW-E　GNSS 备电

| 项 | 内容 |
| --- | --- |
| 问题 | V_BCKP（pin 22）只经 R7 470 Ω 从 3.3 V 取电，配 C5 1 µF，**没有电池或超级电容**。断电即丢星历，每次开机都是冷启动（30 秒以上），而不是热启动（几秒） |
| 来源 | GNSS 模组选型文档 2.3 节 |
| 方案 | 补一颗超级电容（0.1–1 F）或纽扣电池 + 隔离二极管；同时核对 V_BCKP 的电流规格，确认 470 Ω 串联是否造成压降 |
| 为什么是 P0 | 便携设备频繁开关机，**"拿出来就能用"是产品体验的核心**，而冷启动直接违背它 |

### 2.2 P1 建议改（明显收益，代价小）

| 编号 | 改动 | 理由与来源 |
| --- | --- | --- |
| HW-F | **磁珠 FB1 下游补一颗 10 µF**（甚至 22 µF 聚合物电容顺便做 LC 阻尼） | 本轮已加的 FB1 把上游 C7 10 µF 隔开了，OCXO 侧只剩 C4 0.1 µF，**加热器的动态电流撑不住，加了磁珠反而可能比原来更差** |
| HW-G | 1PPS 串阻 R1 由 100 Ω 改为 **22–33 Ω** | 1PPS 的边沿陡度直接决定时间间隔测量的分辨率，应与时钟信号同等对待。来源：GNSS 文档 2.3 节 |
| HW-H | **把 10 MHz 同时送进 OSC_IN** | 当前 10 MHz 只进 PA0，MCU 的 HSE 是独立晶振 Y1。若让 MCU 以 OCXO 为系统时钟，TIC 单次分辨率可从 **100 ns 提到 5.9 ns**，见 3.2 节。这是性价比最高的一项分辨率改善 |
| HW-I | CHIP_EN（pin 8）明确上拉而非悬空 | 悬空依赖内部上拉，换模组后该位置功能会变 |

### 2.3 P2 可选（看目标定位再决定）

| 编号 | 改动 | 说明 |
| --- | --- | --- |
| HW-J | 预留 TDC7200 位置与 SPI | 把 TIC 分辨率推到 55 ps。但在 OCXO 与 GNSS 没升级之前，分辨率不是瓶颈，**不建议现在就上** |
| HW-K | 预留 Lars 式模拟 TIC（HC390 + HC4046 + 二极管 + RC 进 ADC） | 两片 HCMOS 换约 1 ns 分辨率，比 TDC7200 便宜得多。如果 HW-H 做了，收益会重叠，二选一 |
| HW-L | OCXO 热隔离的机械预留 | 泡棉或气凝胶包裹 OCXO。既稳频率又降恒温槽功耗，是便携设计里少见的双赢。但增大体积，需与外壳一起定 |
| HW-M | 外部 16 位 DAC 预留 | 仅当实测证明 PWM 方案的噪声成为瓶颈时才需要。见 3.4 节 |

### 3.2 时间间隔测量（TIC）：三个方案

硬件已经把 10 MHz 送到 PA0、1PPS 送到 PA1。**要测 OCXO 就必须拿 10 MHz 当计数时基**，这决定了当前能做到什么。

| 方案 | 做法 | 单次分辨率 | 需要改板 | 说明 |
| --- | --- | --- | --- | --- |
| **A（当前硬件可做）** | TIM2 用 PA0 的 10 MHz 作外部时钟（ETR 或外部时钟模式），PA1（CH2）输入捕获 1PPS，32 位计数器连续累积相位 | **100 ns** | 否 | **相位连续累积**使等效分辨率随观测时间线性提高：1000 s 观测约等效 1e-10。这是方案 A 能用的关键，不要只看单次 100 ns |
| **A+（软件插值）** | 在 A 的基础上，用内部 170 MHz 再捕获 10 MHz 的边沿做游标插值 | 约 6 ns | 否 | 纯固件技巧，但 MCU 时钟来自独立晶振 Y1，其噪声会进入插值结果，收益需实测确认 |
| **B（HW-H 之后）** | 10 MHz 同时送 OSC_IN，MCU 以 OCXO 为系统时钟，用 170 MHz 直接捕获 1PPS | **5.9 ns** | 是，加一条走线 | 性价比最高的分辨率改善 |
| **C（HW-J 之后）** | 外接 TDC7200 | 55 ps | 是，加芯片 | 在 OCXO 与 GNSS 升级之前不是瓶颈 |

> **更正：** 本项目早先在开源 GPSDO 对比文档里被记为"5.9 ns 定时器捕获"，这是按内部 170 MHz 算的。但那样测的是 1PPS 相对 MCU 自身晶振的时间，**测不到 OCXO**。以 OCXO 为时基时单次分辨率是 100 ns。该文档已更正。

### 3.3 定时器资源冲突（必须在写固件前解决）

**PA0 和 PA5 在 STM32G4 上都映射到 TIM2_CH1。** 如果 TIM2 被用作 TIC（ETR 取 PA0 的 10 MHz、CH2 捕获 PA1 的 1PPS、ARR 置满程做自由运行计数器），那么 PA5 就不能再用同一个 TIM2 输出 PWM——因为 PWM 周期会被满程 ARR 决定（2^32/10 MHz ≈ 429 s），毫无意义。

**必须查 STM32G431 datasheet 的 AF 复用表确认 PA5 还有没有第二个可用的定时器通道。** 三条退路，按推荐顺序：

1. **PA5 直接改用 DAC1_OUT2 输出 EFC。零改板**，固件一行配置切换。代价是 G431 的 DAC 只有 12 位，见 3.4 节。
2. TIC 改用其他定时器，前提是 PA0/PA1 对该定时器有可用 AF。
3. PWM 移到 PA4（也是空闲脚且为 DAC1_OUT1），需改板一条走线。

### 3.4 EFC 输出方式的权衡（不要想当然选 DAC）

| 方案 | 分辨率 | 牵引 5 ppm 时的步进 | 评价 |
| --- | --- | --- | --- |
| **PWM 16 位 + 二阶 RC**（当前） | 65536 级 | 0.76 mHz = **7.6e-11** | **分辨率最好**。载波 2.594 kHz，两级 RC 衰减约 140 dB，纹波可忽略 |
| 内部 DAC 12 位（PA5 或 PA4） | 4096 级 | 12 mHz = 1.2e-9 | **比 PWM 差 16 倍。"用 DAC 更高级"是错觉** |
| 外部 16 位 DAC + 基准 | 65536 级 | 同 PWM | 分辨率与 PWM 相当，优势在于摆脱了"PWM 幅度即 VDD"的基准问题（风险 B） |

> **结论：保留 PWM 方案，不要为了用 DAC 而换掉它。** PWM 的真正弱点不是分辨率而是基准——满量程等于 3.3 V 轨，其噪声按比例调制 EFC。当前把 VCTL 回读进 PB0 的 ADC 是有价值的补救，可在固件里做比例校正。只有当实测证明这成为瓶颈时，才上外部 16 位 DAC + 基准（HW-M）。

## 4. 固件开发计划

八个里程碑。**M0–M3 与 M5–M7 全部不依赖改板，可在现有 v1.0 板上立即开始**，只有 M4 需要等定时级 GNSS 模组到货。

| 目标 | 各外设单独可用 |

| 交付物 | `src/drivers/` 下各驱动 + `src/services/` 下 NMEA 服务 |
| **验收** | **调试串口能打印出 UTC 时间、定位状态、可见卫星数、电池电压；示波器能看到 PWM 占空比随指令变化；ADC 读回的 VCTL 与万用表实测在 1% 内吻合** |
| 依赖 | M0、M1 |

### M3　时间间隔测量

| | |
| --- | --- |
| 目标 | 输出可信的原始相位序列 |
| 任务 | **先解决 3.3 节的定时器冲突**；实现 3.2 节方案 A（TIM2 外部时钟 + CH2 捕获 + 32 位相位连续累积）；处理计数器溢出与 1PPS 丢失；把每秒的相位值经串口输出 |
| 交付物 | `src/services/tic.c`，输出时间戳序列 |
| **验收** | **OCXO 自由运行时，相位序列应是一条带噪声的直线，斜率等于频差。把 EFC 改一个已知量，斜率应按预期变化——这同时验证了 TIC 与 EFC 两条链路的极性与增益** |
| 依赖 | M2 |

### M4　锯齿波（量化误差）修正

| | |
| --- | --- |
| 目标 | 把 1PPS 的有效抖动压低一个数量级 |
| 任务 | 实现 UBX 二进制协议解析（NEO 系列）或 PSTI,00 解析（SkyTraq）；取出 qErr；**注意 u-blox 的 qErr 单位是皮秒，要除以 1000 换成纳秒**；**qErr 仅在 1 Hz 脉冲时有效**；从 M3 的时间间隔值里减掉它 |
| 交付物 | `src/services/gnss_ubx.c` + 修正逻辑 |

## 5. 测量与验证计划

### 5.1 最大的门槛不是电路，是参考源

要验证 1e-11 以上的性能，需要一个比被测对象更好的参考。**用本项目的 MCU 去测本项目的 OCXO，测到的是两者误差的组合。**

| 方案 | 代价 | 能验证到 |
| --- | --- | --- |
| 长时间与 GPS 比对取统计 | 零 | 长 tau 段（交越点以右），足够验证锁定与长稳 |
| 买一台已知良好的成品 GPSDO 做互比 | 中 | 全段，但只能得到两者的组合误差 |
| 铷钟 | 高 | 短中 tau 段，是验证 OCXO 真实短稳的唯一实际途径 |
| 自制 TAPR TICC（BSD 开源，TDC7200，<60 ps） | 低–中 | 作为独立的高分辨率测量工具，不受本项目固件 bug 影响 |

**建议：先用"长时间 GPS 比对"走完 M0–M6，这不需要额外投入；在需要验证短稳时再考虑 TICC 或铷钟。**

### 5.2 必备工具

| 工具 | 用途 | 状态 |
| --- | --- | --- |
| **TimeLab** | ADEV 绘图与分析的事实标准 | 免费，需安装 |
| 限流实验室电源 | OCXO 预热电流曲线、模拟负载阶跃 | 必需 |
| 示波器 ≥100 MHz | 输出波形、PWM 纹波、1PPS 边沿 | 必需 |
| 频率计 | OCXO 的 EFC 牵引曲线实测 | 可用本板的闸门计数替代，精度较低 |
| 万用表 | 供电、压降、VCTL 校核 | 必需 |

## 6. 风险登记册

| 编号 | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| R1 | **NEO 系列与本板焊盘脚位不完全兼容** | HW-C 从"零改板"变成"重画焊盘"，M4 延后 | 下单前完成 24 脚核对；备选 PX1100T |
| R2 | **PA5 没有可用的第二定时器通道** | PWM 与 TIC 冲突 | 见 3.3 节三条退路，首选改用 DAC1_OUT2（零改板） |

| R4 | **U8 的 VDD 未连接，当前板子时钟缓冲可能根本不工作** | 会掩盖其他所有问题 | **列为最优先确认项**，用万用表直接量 |
| R5 | OCXO 预热功耗超出供电能力 | 上电反复重启 | 选型时卡死预热峰值；HW-A 完成后复测 |
| R6 | 固件从零开始，工作量被低估 | 进度延期 | M0 到 M3 是硬骨头，先做；M4 之后每步都有明确验收 |
| R7 | 便携使用的振动与温度冲击吃掉 OCXO 的短稳优势 | 实际性能不如预期 | HW-L 热隔离；选低 g 敏感 OCXO（参考 Andrich 的做法） |
| R8 | 测量结果不可信导致调参方向错误 | 浪费大量时间 | 严守 5.1 节的参考源原则，M3 与 M4 的验收标准都设计成自校验 |

## 7. 执行顺序建议

### 7.1 立即可做的三件事（零采购、零改板、零等待）

1. **用万用表确认 U8 的 VDD 是否真的没连**（风险 R4）。五分钟的事，但它可能是当前板子的拦路虎。
2. **查 STM32G431 datasheet 的 AF 复用表，解决 3.3 节的 PA5 定时器冲突**（风险 R2）。这个结论会决定 M3 的实现方式和是否需要改板。
3. **开始 M0**：搭交叉编译工具链。这是所有固件工作的前提，而且完全不依赖硬件决策。

### 7.2 两轨并行

**硬件轨**（受采购与打样周期约束）：先完成 HW-C 的脚位核对与 HW-A 的方案选择 → 器件采购 → 原理图与 PCB 改动 → 打样 → 硬件验收。

**固件轨**（不占用采购周期）：M0 → M1 → M2 → M3 → M5 → M6，全部可在现有 v1.0 板上完成。**M4 卡在模组到货，但它可以插在 M5 之后补做，不必阻塞主线。**

### 7.3 一个取舍提醒

本计划的 P0 五项都有明确依据，但**它们的收益并不均等**。按对最终 ADEV 的贡献排序：

**HW-C（定时级 GNSS）+ M4（锯齿修正）> HW-A（供电能力，属于"不做就不工作"）> HW-B（EFC 缓冲）> HW-H（TIC 分辨率）> OCXO 升级。**

如果资源有限，**优先把 HW-C 加 M4 这一对做完**——它改善的是交越点右边的长 tau 段，而这正是 GPSDO 相对裸 OCXO 的全部价值所在。
